Step by step: how the new operating point is calculated

  1. Keep the accepted baseline. The Stage 03 network is reproduced before changing anything: 152.799–154.996 L/min per rack and 9.714 kW for the duty-pump bank. The native baseline agrees with the previously saved result.
  2. Reduce speed to match total flow. At 94.31% speed, total flow reaches approximately 24.117 L/s. Individual racks still receive 144.089–146.168 L/min because direct-return header paths have different losses. Matching the sum does not independently set ten branch flows.
  3. Calculate balancing resistance at equal flow. Set each branch to 144.7 L/min in the independent sizing calculation. Solve every header segment at its actual remaining flow. R-10 has the highest unvalved circuit loss. Keep an assumed 15 kPa actual drop at its balancing valve; add the difference in path loss to the other rack valves. The reduced-speed valve drops are 15.00–18.87 kPa.
  4. Solve speed and valves together. Match the pump curve to the critical-circuit requirement, then rerun the native network with those speed and valve settings. Both duty pumps run at 94.48%; all ten racks meet the target. This is the minimum speed only within the fixed topology and declared 15 kPa critical-valve floor. It is not a global pump or valve optimization.
  5. Compare at the same delivered flow. Full-speed balancing also achieves the rack targets, but consumes 9.560 kW. Reducing speed with balancing consumes 8.190 kW: about 1.371 kW less at equal flow. Speed-only uses about 41 W less than the combined case, but leaves the critical rack below target. Calculate power from Δp × Q / (0.75 × 0.90); the cube law is not used as the result.
  6. Check what happens when the system changes. With speed and valve settings held fixed, increasing only R05’s equipment resistance coefficient by 20% reduces its flow to about 135.53 L/min; other racks rise to about 145.25 L/min. This is a separate steady sensitivity case, not a blockage transient. It shows why a fixed manual balance needs review when circuit resistance changes.
Equations, acceptance checks and engineering limits

For equal target flows, define Lᵢ as common + supply-header + return-header + rack losses excluding its balancing valve. Choose Δppump = max(Lᵢ) + 15 kPa, then Δpvalve,i = Δppump − Lᵢ. Convert the actual drop to each quadratic valve’s nominal-flow coefficient. With r = Q / Qnom and speed fraction s, solve the inherited assumed pump curve H = 37s² − 0.5sr − 9r² [m]. All five native cases reached their final export time with finite results. Accepted checks include mass continuity, loop-pressure closure, pump-work numerical energy closure, reproduction of Stage 03, balanced-rack error <0.001 L/min and independent exact-Colebrook flow agreement <0.001%. The reduced-speed cases use direct nonlinear initialization after the default homotopy attempt failed. Accepted runtime logs and prior diagnostic attempts are downloadable; the compiler’s redundant-start/nominal alias warning is retained. The 0–1 s export repeats a steady solution; it is not a physical one-second operating test.

These are numerical checks of the assumed network, not experimental validation. Pipe IDs and routing are inherited; device curves, fitting K values and efficiencies remain provisional. No valve actuator dynamics, pressure-controller stability, physical heat-exchanger performance, water hammer, NPSH qualification or standby transition has been solved. The 15 kPa static-valve floor must not be reused as a pressure-independent valve’s required operating differential.

Flow-balancing approaches / Literature → model evidence → next decision

Balance the branches. Control the pressure they actually need.

The references below explain established hydronic methods. Our numerical cases test this particular independent network; they do not establish AWS/Google practice or qualify a commercial device. Manual balancing is the first implementable model stage. Dynamic alternatives need device operating ranges and control models before a fair energy comparison.

Why start with speed plus static balancing?

Our baseline is already fairly uniform: only 1.43% rack spread. Most of this stage’s power reduction comes from removing overall over-flow, while balancing makes each rack meet its target. The combined case uses slightly more power than speed-only because it serves the critical rack rather than just the average.

Where the next analysis should go

Use measured or supplier rack/valve curves, then compare manual settings against a real PICV or rack-flow controller under unequal loads, filter loading and rack isolation. Add critical-branch pressure sensing to reset pump speed. CFD is most useful for uncertain tee/manifold losses; it is not needed to calculate a known valve’s Kv.

Public technical references and how we used them

  • US DOE / Hydraulic Institute · Improving Pumping System Performance, second edition ↗Section 11, printed pp. 51–53: throttling dissipates fluid energy; reducing pump output can avoid that excess. We test this with the full-speed and reduced-speed balanced cases at equal flow. The result uses the solved network and fixed efficiencies.
  • Caleffi idronics 34 · Introduction to hydronic balancing ↗January 2024, “A naturally unbalanced system”: different shared-path resistances affect parallel branch flow. Our direct-return flow plot and calculated valve drops quantify that mechanism for ten racks.
  • Danfoss · ASV-PV automatic balancing data sheet ↗April 2019, pp. 1–3 and 6: group differential-pressure regulation and terminal flow limitation. This supports the DPCV concept; we have not selected or simulated this product.
  • Danfoss · AB-QM pressure-independent valve data sheet ↗March 2022, pp. 1–2: integrated pressure regulation, flow setting and size-dependent flow/Δp ranges. This defines the inputs needed for a future PICV comparison; no catalog performance has been substituted for our static-valve model.
  • Caleffi · Two-pipe reverse-return discussion ↗April 2024: more comparable paths improve inherent balance, while real systems only approximate equal resistance. We retain this as a topology candidate requiring a separate CAD/network comparison.
